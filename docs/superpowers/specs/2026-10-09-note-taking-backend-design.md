# Note-Taking Backend — Design Spec

**Date:** 2026-10-09
**Stack:** Node.js, Express, PostgreSQL, Prisma ORM

---

## Overview

A REST API backend for small teams to submit and retrieve notes. Teams access it through URL endpoints — no installation required. The frontend (managed separately) sends JSON payloads; this service stores and serves them.

---

## Data Model

### User
| field | type | notes |
|---|---|---|
| `id` | UUID | PK, auto-generated |
| `email` | String | unique — primary identifier |
| `name` | String | display name, not unique |
| `created_at` | DateTime | auto |

Email is the stable unique identifier. Name is display-only and may be duplicated across users.

### Category
| field | type | notes |
|---|---|---|
| `id` | UUID | PK, auto-generated |
| `name` | String | unique (e.g. `"engineering"`) |
| `is_active` | Boolean | default `true` |
| `created_at` | DateTime | auto |

Categories live in their own table so admins can add new ones at runtime without a migration or deploy. Seeded on first run with: `marketing`, `sales`, `engineering`, `hr`, `personal`, `miscellaneous`.

### Note
| field | type | notes |
|---|---|---|
| `id` | UUID | PK, auto-generated |
| `title` | String | |
| `body` | String | |
| `category_id` | UUID | FK → Category |
| `user_id` | UUID | FK → User |
| `created_at` | DateTime | auto |

---

## Endpoints

### Notes
| method | path | description |
|---|---|---|
| `POST` | `/notes` | Create a note. Payload: `email`, `name`, `title`, `body`, `category_id`. Creates User if email is new. |
| `GET` | `/notes/:id` | Get a single note by ID |
| `GET` | `/notes/user/:email` | All notes by a user |
| `GET` | `/notes/category/:categoryName` | All notes in a category |
| `GET` | `/notes/user/:email/category/:categoryName` | All notes by user + category |

### Categories
| method | path | description |
|---|---|---|
| `GET` | `/categories` | List all active categories (for frontend dropdowns) |
| `POST` | `/admin/categories` | Add a new category |

The `/admin` namespace is reserved for privileged operations. No auth is implemented in this iteration but the namespace signals intent for future gating.

---

## Business Logic

**Note creation (`POST /notes`):**
1. Look up User by `email`
2. If not found, create a new User with the provided `email` and `name`
3. Validate `category_id` exists and is active
4. Create and return the Note

**Category lookup:** Routes using `:categoryName` resolve the name to a category ID before querying notes.

---

## Deferred (Next Iterations)

- **Pagination:** All list endpoints currently return all matching records. Frontend is expected to implement pagination UI. Backend will need `limit`/`offset` or cursor-based pagination before any real-scale deployment.
- **Authentication/Authorization:** No auth in this iteration. Admin endpoints (`/admin/*`) are unsecured. Future iteration should add auth middleware and restrict admin routes to privileged users.

---

## Error Handling

A central `errorHandler` middleware catches all unhandled errors and returns consistent JSON responses:

```json
{ "error": "message here" }
```

Routes return:
- `400` for validation errors (missing fields, invalid category)
- `404` for not found
- `500` for unexpected server errors
